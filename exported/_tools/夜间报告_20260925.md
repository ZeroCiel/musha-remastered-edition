## 两个重大发现（修了 opencode 工具链的两个历史遗留坑）

### ① anim 图集解码视图是垂直倒序存储的（引擎端自带翻转）

- 证据：回城石 / 信差包 / musha 角色脸 / **官方 wilson swap_icon** 四路 MAE 实测，
  图集存储 vs 源图全部是"上下翻"完胜（13~35 vs 79+）；而这些素材游戏内都是正的。
- KTEX flag 家族：anim tex = `0xfffd…`（引擎加载时翻转），图标 tex = `0xfffc…`（不翻）。
  flag 高位随宽度变化（128→0x2 … 2048→0x8），是尺寸元数据不是翻转位。
- 影响：`dump_anim_frames.py` 的预览一直**上下颠倒**（placement 对、像素倒）。
  **游戏里素材是正的，别因此改源图**；本工具已补 FLIP_TOP_BOTTOM。
  （opencode 的文件没动，只在此存档。）

### ② scml.exe 把大图切瓦片分散打包 + 多页图集

- 每帧顶点按 **6 个一组 = 一个 quad**（88×132 → 4 块 44×66）；素材装不下一页图集时
  分页（atlas-0/1/...），每 quad 顶点第 6 个 float（sampler）标页码。
- 按整帧 uv 包围盒采样会串到别的素材（演示动画 frame_00/04 "双挂坠"穿帮的根源，
  视觉审查员独立审了出来）。本工具按 quad 逐块采样 + 按页取图，已修复。
- 回城石上逐 quad 与旧 bbox 法 0 像素差（单素材图集两种等价），wilson 回归正常。

### 顺带：scml.exe 调用坑

输入必须用相对 cwd 的**裸文件名**（cwd = scml 目录），输出给绝对路径；
否则它把输入路径拼到输出目录下直接 Could not open。
