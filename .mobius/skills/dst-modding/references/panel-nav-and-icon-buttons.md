# 面板导航 / 图标按钮（缩放 · 配色 · 无底色）

适用：面板要加"多页导航"，或用户给「图标缩小到40% / 淡黄色 / 没有底色 / 移动+8 下30」这类微调。
（musha 0.7.6，2026-09-10 实测）

## 导航骨架
- **右上三角** = `ImageButton("images/global.xml","square.tex")` + 子 `Text(">")`；
  点一下展开/收起 5 项列表（`self.nav_list.shown` 判开合）。
- **展开列表** = 一个 `Widget` 容器，里面 5 个 ImageButton，`SetPosition(0, -(i-1)*56)` 往下排。
- 图标美术没到位时**先用文字**（用户明确说"暂时用文字代替"）。把导航抽成
  `BuildNav()` / `SetActivePage(name)` 两处，将来换成"一排真图标"只改这两处。
- 切页只 `Show()/Hide()` 各页容器，不重建 Screen；细节见
  `references/screen-scrolling-grid.md` 的「面板多页化」节。

## ★ ImageButton 缩放铁律：必须关 scale_on_focus
`ImageButton` 在 focus 时会把**自身 image 的 scale** 设成 `focus_scale`（默认 **`{1.2,1.2,1.2}`**，不是 `{1,1,1}`）。
**给按钮 `SetScale(0.4)` 后，鼠标一悬停就被拉回** —— 表现像"缩放没生效 / 闪一下"。

★ 两个方向的坑都要防：
- 缩过放的按钮 → 悬停被拉回 100%（下面的三行修法）
- **没缩过的按钮** → 悬停反而被**放大 1.2 倍**。只传一个贴图的按钮
  （`ImageButton("images/global.xml","square.tex")`）会被判定 `image_focus == image_normal`，
  `OnGainFocus` 的判定**必然成立** → 底图放大 1.2 倍，而叠上去的白描边是**子节点、不跟着缩放**
  → **底色块涨出框外**。用户原话：「底色会爆出来、外框看起来很大」。
  Klei 源码那行上方自己写着：`-- Common bug: you probably want scale_on_focus = false`。

```lua
local S = 0.4
b:SetScale(S, S, S)
b.scale_on_focus = false                 -- ★ 不关就是白改
b.normal_scale = { S, S, S }             -- 两套都写成同一个值，双保险
b.focus_scale  = { S, S, S }
```

## ★ SetScale 父子连坐：文字会一起缩
`SetScale` 作用在整棵控件树上，子 `Text` 一起缩。28pt 中文 ×0.4 ≈ 11pt，糊成一团。
- 要"整体缩小" → 直接对按钮/容器 `SetScale`，接受文字变小。
- 要"**只缩框不缩字**" → 别用 SetScale，改成 `ForceImageSize(w*0.4, h*0.4)` + 行距重算，
  字号单独给。判据：用户说"文字不会缩小"→ 走这条。

## 无底色按钮（只留符号）
```lua
b:SetImageNormalColour(1, 1, 1, 0)       -- 底色透明
b:SetImageFocusColour(1, 1, 1, 0.12)     -- ★留一点 hover 反馈，否则鼠标移上去毫无反应像点不到
```
符号靠子 `Text` 上色。三角用字符 `">"`（bp50 未必有 ▶/▼，要真三角形得等美术）。

## 浅色底上的配色陷阱
底色是浅色书页（`bookpage_bg`）时，**淡黄符号画上去几乎看不见**。
用户要"淡黄图标"时先说明这一点，并给备选（深棕 / 深橙 / 加细描边）。
同理：淡黄底上的字要用深色（`0.40,0.33,0.22`），当前页高亮用深橙（`0.80,0.32,0.10`）——
不要用浅色字配浅色底。

## ★ 微调词有歧义时：严格按字面，只动被点到的元素
实测踩坑：用户说「**图标**缩小到40%」→ 我把「三角 + 展开列表」**整组**都缩了 →
下一轮被纠正「三角放大到70%，里面展开的文字不会缩小」。
- 规则：用户点名的元素就**只动那一个**，不要"顺手把同组的一起改"。
- "图标 / 那个条 / 前面第三版"指哪一组拿不准时，在回话里**写明"我改的是 X"**让他一句话纠正，
  比默默扩大改动范围好（比反问省一轮）。
- 数值词口径：`+8 下30` = 右移 8 / 下移 30；单位默认像素（用户嘴上说"厘米"时先按该数字当像素做，
  并在回话里点明"按 3px 算的，若指 3 厘米≈113px 说一声"）。

## 用户描述视觉参考时"别加戏"
用户说「类似黄色星星那种**像素感觉**」≠ 要加像素块纹理。
先把**颜色**改到位，不要叠加上位的"效果"（纹理 / 图案 / 质感）——
实测被一句「**不是**——类似于淡黄色就行」打回，白写一段代码。

## ★ 按编号回指：用户说「N错了」= 撤回我回复里的第 N 条
我回复用「1. / 2. / 3.」分条时，用户会直接回「**2错了**」或「**不透明 2错了**」。
- 含义 = 我第 2 条**整条**判错，要**恢复原状**，不是在那个方向继续调参数。
- ★ 实测：用户说「三角图标放大到70% **没有底色** 里面展开的文字不会缩小」，
  我把"没有底色"套在**第一个元素**（三角）上做成透明 → 被回「**不透明 2错了**」。
  正解：没有底色是给**展开列表**的，三角要的是**不透明**。
- 结论：多个元素 + 多个修饰语的一句话，先在回话里写明"哪个修饰语归哪个元素"再动手，归错成本是一整轮。
  （和上一节"只动被点到的元素"是一体两面：既不扩大，也不挪位。）

## 白色细框 + 底板（零美术拼控件）
底板 = `ImageButton("images/global.xml","square.tex")` + `ForceImageSize`；
白框 = 4 条子 `Image("images/global.xml","square.tex")`，2px：
```lua
for _, ln in ipairs({ {0, h/2-1, w, 2}, {0, -(h/2-1), w, 2},
                      {-(w/2-1), 0, 2, h}, {(w/2-1), 0, 2, h} }) do
    local line = b:AddChild(Image("images/global.xml","square.tex"))
    line:SetSize(ln[3], ln[4]); line:SetPosition(ln[1], ln[2]); line:SetTint(1,1,1,0.9)
end
```
- ★ 描边是**子节点**：底板尺寸一变（例整条缩到 76%，150x52 → 114x40），4 条线必须同步改，否则框错位。
- 缩小组件后 2px 描边**视觉上会变粗**（框小了）→ 被嫌粗就降到 1.5px。
- "物质的反馈" = 悬停时底板**明显变亮**（`SetImageFocusColour` 给更亮的色），比只改描边更"按得下去"。

## 质感：纯灰黑会被判"没质感"
实测用户对深灰黑按钮的评价是「**灰黑色 几乎没质感**」。同一套皮里想要质感：
- 底板换**蜡黄 / 黄灰**系（例 `(0.70,0.62,0.42)`），配淡黄符号 → 像旧书上的铜扣。
- 给它加**和相邻控件同一套的白描边** —— 看起来才像一个"实体"，不是贴图。
- 淡黄底上字必须转深色（`0.32,0.26,0.18`）；悬停底板变亮 `(1.00,0.97,0.80)`。
