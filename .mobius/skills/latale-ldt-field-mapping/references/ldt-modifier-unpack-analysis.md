# LDT修改器.exe 脱壳分析

## 基本信息

- **路径**: `D:\LaTale\LDT修改器.exe`
- **大小**: 619,520 字节
- **语言**: 易语言编写
- **壳**: UPX 3.91 改版壳（易语言专用变种）
- **文件特征**: PE32 (GUI), Intel 386

## 壳特征

| UPX0 | 901,120 | 0x1000 | 0 | 0x400 | 压缩后展开区 |
| UPX1 | 569,344 | 0xDD000 | 566,272 | 0x400 | 压缩数据+stub |

### 为什么UPX官方版不认

**已测试UPX版本全部失败**: 3.03 / 3.09 / 3.91 / 4.2.4

**原因**:
- 版本标记在0x3DA: `\x003.91`
- UPX!标记在0x3E0（标准格式）
- **Subsystem=0**（应为2=GUI）——易语言打包器修改了PE头
- 可能还改了其他校验字段

UPX识别逻辑校验多个字段的checksum，易语言打包器修改后导致UPX拒绝识别。

### 壳结构

```
[PE头] → [UPX0: 无原始数据] → [UPX1: 压缩数据+stub]
```

UPX1节(RAddr=0x400):
- 0x400: stub入口代码
- 0x3DA: "3.91" 版本标记
- 0x3E0: "UPX!" 标记
- 后续: NRV解压缩引擎 + 过滤表 + 压缩数据

## 脱壳思路

### 方案1: 手动修复Subsystem
PE头Subsystem 0→2(GUI), 再试UPX -d。大概率仍不行。

### 方案2: OD/IDA手动脱壳
载入 → UPX0入口下断 → 跑到OEP → Scylla dump+IAT修复。

### 方案3: 易语言专用脱壳工具
搜"易语言脱壳机""E盾脱壳"等。

### 方案4: Python手动解压
NRV算法有开源实现，可从UPX1提取压缩数据解压+重建PE。
工作量大，不如方案2/3。
