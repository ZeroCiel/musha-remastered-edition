# ITEM_2.Name字段真相（验证修正 2026-05-28）

## 本文档说明

记录ITEM_2.LDT中_Name字段读取修正过程——从误解为"描述才是名称"到确认"名称就是中文名"的全部证据链。

**2026-05-28修正**：_Name 就是**直接可用的中文商品名**，不是数字ID引用。

### 验证证据

| 道具ID | 原解读 | 修正后的解读 |
|--------|--------|-------------|
| 30245642 | _Description="活动黑色短裤" | _Name="活动黑色短裤" ← 正确 |
| 70140175 | _Description="愉悦粉红色珠珠凉鞋" | _Name="愉悦粉红色珠珠凉鞋" ← 正确 |

### 读错原因

`ldt_writer.read_rows()` 返回 `row[0]=_RowId`（LDT内置行号），所以所有列索引需要+1。原脚本直接用了 `row[name_idx]` 而不是 `row[name_idx+1]`。

## 补充：_Name的第三种形态（2026-05-29发现）

某些时装（如雪初音2011~2014系列24件）的_Name字段存储的是**纯数字字符串**（"1""2""3""4""5""7"），而_Description是完整的日文描述（"雪ミク2014魔女帽子"等）。

### 判定标准

这24件道具（ID范围为90481604~90581604等）的特征：
- `_Name` = 单数字字符串（"1"~"7"），不是GLString引用（GLOBAL_STRING中无对应_ID）
- `_Description` = 日文实际名称（"雪ミク2011スカート""初音ミクGP ver. フェザー"等）
- `_Category/_Num/_ColorID` 三段正好组成ID后6位（如 904/816/04 = 90481604）
- `_Type=1 _SubType=2`（时装）
- `_PosID1=1`（他乡端头饰类，非标准风格/衣服/裤子等）
- `_CashCheck=1`（已允许上架，端自带已开启）
- 无时限（_Time_Type=0 _Lifetime=0）

### 实操建议：追加CASH_SHOP时的_Name取值

当_Name是数字（非中文）时：
1. 优先用GLOBAL_STRING.LDT查_StringID → _Text（如果存在匹配）
2. 如果GLOBAL_STRING无匹配（如雪ミク系列），直接用_Description的前30~40个字符作为商品名
3. CASH_SHOP已有记录显示他乡端开发者将雪ミク系列的商品名手工缩写为"雪初音_2011"格式
